# 35: Analyze pilot usage and select Phase 2 workstreams

**What to build:** Turn Phase 1 pilot evidence into a documented Phase 2 prioritization decision, separating observed user problems from speculative roadmap ideas before implementation tickets are created.

**Blocked by:** 26: Pass the Phase 1.1 reimbursement gate.

**Status:** ready-for-agent

- [ ] The analysis uses sanitized Phase 1.0/1.1 usage, correction, unsupported-intent and retention metrics.
- [ ] Direct feedback from the two-user and broader family pilots is summarized without PII.
- [ ] Budget/trip, multi-currency, statement import, shared views and financial guidance are evaluated independently.
- [ ] Each candidate records observed demand, expected benefit, privacy risk, domain complexity and operational cost.
- [ ] Candidates unsupported by evidence remain deferred rather than becoming implementation tickets automatically.
- [ ] The decision identifies which workstream, if any, should receive focused requirement discovery next.
- [ ] Phase 1 personal-ledger and privacy invariants are treated as non-negotiable constraints.
- [ ] The result is approved by the product owner before any Phase 2 implementation breakdown.
