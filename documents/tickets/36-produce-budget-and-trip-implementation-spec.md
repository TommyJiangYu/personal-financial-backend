# 36: Produce an implementation-ready Budget and Trip spec

**What to build:** Conduct focused product discovery and produce an approved implementation-ready specification for optional budgets and trip grouping without changing Transaction ownership or reimbursement accounting.

**Blocked by:** 35: Analyze pilot usage and select Phase 2 workstreams.

**Status:** ready-for-agent

- [ ] The discovery validates that users need planning/grouping beyond existing date-range reports.
- [ ] Budget and Trip are defined as separate planning/grouping concepts rather than new ledgers.
- [ ] The spec defines how personal Expense, cash paid, PAYABLE and RECEIVABLE affect budget totals.
- [ ] Trip date suggestions require user confirmation before grouping Transactions.
- [ ] Overspend notifications are opt-in with explicit frequency and privacy behavior.
- [ ] Edit, delete, reimbursement and account-deletion effects are specified.
- [ ] External behavior, acceptance criteria, testing seam, migration and out-of-scope are complete.
- [ ] No implementation ticket is created until the product owner approves the spec.
